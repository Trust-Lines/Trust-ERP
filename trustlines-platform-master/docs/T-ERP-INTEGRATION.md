# T-ERP ↔ Trust System (trust-excel) integration

T-ERP (https://t-erp.vercel.app) shows and edits the Projects data that lives in the Trust
System (https://trust-excel.vercel.app). During the page-by-page move **the Trust System
stays the only place the data lives**. T-ERP does not copy data into its own database. It
reads and writes through the Trust System API, so every rule keeps working: PF code
generation, TR-STOCK stock usage, status/date automation, the trash bin, the activity log
and live updates.

---

## 1. How T-ERP connects

```
Browser (T-ERP page) ──► T-ERP server route /api/trust/* ──► https://trust-excel.vercel.app/api/*
                                    adds  X-API-Key: <TRUST_API_KEY>
```

- **The key is only used on T-ERP's server.** Never put it in browser code: anyone who
  opens the site could read it from the JS.
- Server-to-server calls need no CORS setup.
- The key acts as the Trust System user set in `INTEGRATION_USER_EMAIL` (currently an
  ADMIN), so it can read and write every page. Changes appear in the Trust System activity
  log under that user.

### 1b. Proxy route in T-ERP

Next.js (App Router), `app/api/trust/[...path]/route.ts`:

```ts
// Forwards /api/trust/<path> to the Trust System API with the server-side key.
// Only T-ERP's own logged-in users may reach it: keep this route behind T-ERP's auth check.
import { NextRequest } from 'next/server';

const BASE = process.env.TRUST_API_URL!;
const KEY = process.env.TRUST_API_KEY!;

async function forward(req: NextRequest, { params }: { params: { path: string[] } }) {
  // TODO: replace with T-ERP's own session check; return 401 when not logged in
  const url = `${BASE}/${params.path.map(encodeURIComponent).join('/')}${req.nextUrl.search}`;
  const hasBody = !['GET', 'HEAD'].includes(req.method);
  const res = await fetch(url, {
    method: req.method,
    headers: {
      'X-API-Key': KEY,
      ...(req.headers.get('content-type') ? { 'Content-Type': req.headers.get('content-type')! } : {}),
    },
    body: hasBody ? await req.arrayBuffer() : undefined,
    cache: 'no-store',
  });
  return new Response(res.body, {
    status: res.status,
    headers: {
      'Content-Type': res.headers.get('content-type') || 'application/json',
      ...(res.headers.get('content-disposition') ? { 'Content-Disposition': res.headers.get('content-disposition')! } : {}),
    },
  });
}

export { forward as GET, forward as POST, forward as PATCH, forward as PUT, forward as DELETE };
```

On a different stack (Express, a plain Vercel function, …), do the same: forward method,
path, query and body; add `X-API-Key`; return status, body and content type unchanged.

> **Important:** this route has to sit behind T-ERP's login. Without that check, anyone who
> knows the T-ERP address gets full Trust System access through it.

## 2. Endpoints the Projects page uses

All paths are relative to `/api/trust` in T-ERP (i.e. `/api` in the Trust System).
Bodies are JSON. Errors come back as `{ statusCode, message }` with 400/401/403/404.

### Projects
| Method | Path | Use |
|---|---|---|
| GET | `/projects?page=1&limit=50` | list, paged: `{ data, meta: { totalPages, … } }`; load pages 1…`meta.totalPages` (the server caps `limit`). Optional filters: `bucket`, `status`, `search`, `sortBy`, `sortOrder` |
| GET | `/projects/:id` | one project with its rows |
| POST | `/projects` | new project |
| PATCH | `/projects/:id` | edit project fields |
| PATCH | `/projects/:id/move-region` | move to another region/bucket |
| PATCH | `/projects/bulk/half` | bulk "half" assignment |
| DELETE | `/projects/:id` | move to the trash (can be restored) |

`bucket` (region): `TLINES_NE`, `TLINES_SE`, `TLINES_NW`, `CVW`, `TLINES_HQ`, `TLINES_TC`.

### Project rows (items)
| Method | Path | Use |
|---|---|---|
| GET | `/projects/:projectId/items` | rows of a project |
| GET | `/projects/:projectId/items/:itemId` | one row |
| POST | `/projects/:projectId/items` | new row: the **PF code is generated by the server** |
| PATCH | `/projects/items/:itemId` | edit a row (send only the changed fields) |
| DELETE | `/projects/:projectId/items/:itemId` | move a row to the trash |

**Don't compute PF codes, statuses, dates or totals in T-ERP.** Send the change and show
what the server returns. The server handles PF codes on vendor/type/order-type changes,
fixed M01–M03 codes, FURNITURE → F codes and status-date automation.

### Dropdown / reference data
| Method | Path |
|---|---|
| GET | `/vendors` |
| GET | `/order-types` |
| GET | `/custom-types/available` (and `/custom-types/global`) |
| GET | `/payment-rules` |
| GET | `/pf-groups` |
| GET | `/today-pf` |

### TR-STOCK rows (stock usage)
A row whose vendor is TR-STOCK takes products from Trust Stock:

| Method | Path | Use |
|---|---|---|
| GET | `/trust-stock/usage/products` | products that can be taken |
| GET | `/trust-stock/usage?projectItemId=<id>` | what this row took/reserved |
| POST | `/trust-stock/usage/movements` | take / reserve / return: `{ projectItemId, takenBy, lines: [{ productId, take?, reserve?, return? }] }` |
| GET | `/trust-stock/usage/people` | "taken by" names for the dropdown |
| DELETE | `/trust-stock/usage/:id` | undo a movement |

## 3. Live updates (optional, recommended)

When someone edits in the Trust System, T-ERP can update on screen without a refresh:

1. `GET /realtime/config` → `{ enabled, url, key, channelPrefix }`
2. In the browser, use `@supabase/supabase-js`: `createClient(url, key)`, then subscribe to the
   **broadcast** channel `${channelPrefix}:projects` (and `${channelPrefix}:trust-stock` for
   stock).
3. Each message is `{ event, data, excludeUserId? }`. On a project/row event, reload that
   project with `GET /projects/:id`. Events with `excludeUserId` equal to the integration user
   are T-ERP's own changes and can be ignored.

`url` and `key` are the public (publishable) Supabase values. The channel prefix is only given
to authenticated callers, which is why it comes from the API.

Without this, reload the data after each save and on page focus.

## 5. Limits and housekeeping

- Rate limit: **200 requests per minute** per IP. Load lists page by page and don't poll in tight loops.
- Request body limit: 1 MB JSON; PDF uploads 4 MB.
- **Turn access off:** delete `INTEGRATION_API_KEY` in trust-excel and Redeploy.
- **Rotate the key:** set `INTEGRATION_API_KEY=<new>,<old>` and redeploy trust-excel, switch
  T-ERP to `<new>`, then remove `<old>`. Access never goes down in between.
- At the very end of the move (backend/database to T-ERP), this proxy is replaced; the API
  shapes above are the contract to migrate.
